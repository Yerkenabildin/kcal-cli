# AGENTS.md

Guidance for AI coding agents working in this repository (Claude Code reads it via the
`CLAUDE.md` symlink).

## What this is

A zero-dependency Node.js (>=18) CLI facade for the **private, unofficial** YAZIO food-diary
API, using only built-in modules (`node:fs`, `node:crypto`, `node:test`, global `fetch`).
Do not add npm dependencies — `dependencies` in `package.json` is intentionally empty and CI
runs `npm pack --dry-run`.

It is the only YAZIO API boundary in the wider integration. A Hermes plugin
(`hermes-plugin/`) shells out to this CLI; it never speaks HTTP itself.

## Commands

```bash
npm test                                    # full suite: node --test (mocked fetch, no network)
node --test test/client.test.mjs            # one test file
node --test --test-name-pattern="<regex>"   # tests matching a name
npm run test:live                           # opt-in live tests against the real API (YAZIO_LIVE_TESTS=1)
node --check bin/yazio.mjs                  # syntax check (also in CI)
node bin/yazio.mjs <command>                # run without linking
```

CI runs `npm test`, `node --check` and `npm pack --dry-run` on Node 18/20/22. No linter, no
build step.

## The API this talks to

Private, reverse-engineered, and **not documented by YAZIO**. The field guide is
[`yazio-community/yazio-api-specification`](https://github.com/yazio-community/yazio-api-specification)
(API version 22, `https://yzapi.yazio.com/v22/`). It was inferred from one account's captured
traffic: an endpoint the app never exercised is simply absent, and a field that was null
throughout is typed from that null. **Tolerate unknown fields; never treat schema absence as
proof of API absence.**

Quirks that are encoded in this codebase rather than left to a caller — see
`docs/PRIVATE-API-RISKS.md` for the full list and the evidence behind each:

- Every non-token request needs an accepted app `User-Agent`; an unrecognised version answers
  `403 {"error":"version_blocked"}` on everything except the token exchange.
- Product search requires non-blank `sex` and `countries`, and is ranked by `Accept-Language`.
- Product nutrients are **per one base unit, not per 100**. Energy is kcal, everything else grams.
- A consumed item's `id` is **generated by the client**. That is the idempotency key.
- Writes take a full local timestamp `YYYY-MM-DD HH:MM:SS`; reads address a day by `YYYY-MM-DD`.
- Writes and deletes answer `204` with an empty body — including deletes that removed nothing.
- `daytime` outside `breakfast|lunch|dinner|snack` is accepted silently and hides the entry.

## Architecture

Everything flows through one HTTP chokepoint. Command modules never call `fetch` directly
(except the OAuth exchange in `auth.mjs`).

- **`bin/yazio.mjs`** — entry point. A static `COMMANDS` map lazily `import()`s one module per
  subcommand. Each module exports `async run(positionals, flags, ctx)` and a `knownFlags` Set;
  the return value is printed as pretty JSON on stdout, and a thrown `CliError` is printed as
  JSON on stderr with the error's `exitCode`.
- **`src/errors.mjs`** — the `CliError` hierarchy mapping error kinds to exit codes, plus
  `errorPayload()`, which runs a redaction pass so a credential can never reach a printed payload.
- **`src/util.mjs`** — argument parsing, JSON output, and the date/timestamp helpers. The two
  YAZIO date formats are **not** interchangeable, so `toDateString` (reads) and
  `entryTimestamp`/`toTimestamp` (writes) are deliberately separate functions.

## Exit codes

`0` success · `1` API/runtime · `2` usage/validation · `3` auth required · `4` confirmation
required · `5` ambiguous match or verification conflict · `6` write result unknown · `7` API
changed.

Codes 0–5 match `kinopub-cli` exactly so the two CLIs stay comparable. **6 and 7 are a
deliberate extension for this API**: a write whose server-side outcome could not be established
is a different situation from a conflict and needs its own recovery path, and a private API that
has moved out from under us must not be reported as a generic failure.

Destructive commands never prompt; without `--yes` they return `confirmation_required` plus the
exact retry command.

## Conventions

- New subcommand: add a lazy import to `COMMANDS` in `bin/yazio.mjs` and a module in
  `src/commands/` exporting `run()` and `knownFlags`.
- Read configuration from `src/config.mjs`, never `process.env` directly.
- Tests mock `globalThis.fetch`; the default suite must stay network-free. Live tests go in
  `test/live.test.mjs` behind `YAZIO_LIVE_TESTS=1`.
- Name units in output keys (`energy_kcal`, `protein_g`) so a number cannot be misread.
- The account password is never stored, logged, or passed in argv. `yazio login` reads it from a
  hidden TTY prompt and writes only tokens.
